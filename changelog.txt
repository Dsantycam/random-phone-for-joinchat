== Changelog ==

= 4.5.0 =
* Nuevo panel "Reparto de contactos" (en el menú de Joinchat, o en Ajustes si
  Joinchat está ahí): visitantes asignados y aperturas de WhatsApp por teléfono
  y por día, tasa de contacto, equilibrio del reparto frente a lo que
  corresponde a cada número por sus cupos, ronda actual de la bolsa, origen
  (botón flotante, ventana de chat, botones y enlaces, apertura automática),
  móvil/escritorio y páginas con más contactos. Periodos de hoy, 7, 30 y 90
  días, 12 meses o fechas a elegir, comparación con el periodo anterior,
  tabla ordenable y exportación a CSV (lista para Excel).
* Aviso cuando el servidor no responde a muchos visitantes y el número lo
  tiene que elegir el navegador (caché, cortafuegos o plugin de seguridad
  bloqueando admin-ajax.php).
* Las estadísticas son contadores diarios en una tabla propia (wp_jcrp_stats),
  sumados con una sola consulta atómica: nada sobre los visitantes. Se crea al
  activar o, al actualizar, con la primera visita; si no se puede crear, el
  reparto sigue igual y se reintenta cada hora. Se borra al desinstalar.
* Nunca afectan al reparto: cualquier fallo al contar se ignora, y el aviso
  de apertura sale después de abrir WhatsApp (sendBeacon) sin retrasarlo.
  Solo se cuentan teléfonos de la lista y se descartan robots.
* Filtro joinchat_random_phone_stats para apagarlas.

= 4.4.0 =
* Compatible con todas las versiones de Joinchat, desde la 3.0 (cuando aún se
  llamaba "WAme") hasta la 6.4.4. Antes exigía la 6.0. Probado con el código
  real de 20 versiones: 3.0.0, 3.0.3, 3.1.0, 3.1.4, 3.2.0, 3.2.3, 4.0.10, 4.1.15,
  4.2.0, 4.3.2, 4.4.3, 4.5.20, 5.0.17, 5.1.8, 5.2.4, 6.0.10, 6.1.3, 6.2.3,
  6.3.2 y 6.4.4.
* Nueva capa de compatibilidad (includes/class-joinchat-random-phone-compat.php)
  que resuelve lo que cambia entre versiones: el prefijo de hooks, opción y
  metadatos (whatsappme_ en la 3.x, joinchat_ después), los nombres de los
  scripts y estilos de cada versión, y si existe el filtro de permisos.
* Web: el reparto funciona con el objeto wame_public (3.x) y joinchat_obj
  (4.x+), con whatsapp_link (3.2-5.x) y get_wa_link (6.x), y escucha también
  los eventos jQuery de Joinchat 3.x-5.x (whatsappme:open, joinchat:open,
  joinchat:show), que no llegan a los escuchadores nativos. En WAme 3.0/3.1,
  que construye el enlace en una función privada, el número se corrige en el
  evento whatsappme:open. Los QR de Joinchat 4.4-5.x (jQuery, kjua) también.
* Panel de teléfonos: banderas, nombres de país, formato y prefijo automático
  con intl-tel-input v16 (3.x/4.0), v17 (4.1-4.5), v18 (5.x), v25 (6.0-6.2) y
  v29 (6.3+). En v16-v18 la librería de validación (libphonenumber) se carga
  aparte y Joinchat solo lo hacía para su propio campo, que este panel
  sustituye: ahora la carga el plugin desde el mismo sitio que Joinchat.
* Las dependencias del panel se calculan con los scripts que existen en cada
  versión: una dependencia inexistente hacía que WordPress no cargara el panel.
* Cajas de entrada, categoría (4.3+) y autor (nuevo, Joinchat 6.4+): si el
  marcado no es el esperado se sustituye solo el campo, y si no se encuentra
  se deja el de Joinchat (antes daba avisos de PHP y rompía la caja).
* Arreglado: una categoría o un autor con su propio teléfono se seguía
  repartiendo entre la lista del sitio (solo se comprobaba en las entradas).
* La página de permisos por rol solo se activa con Joinchat 4.2+, que es
  cuando apareció el filtro que necesita.
* Nuevos bancos de pruebas: test-versiones.js (reparto en la web con las 20
  versiones, 124 pruebas), test-admin-versiones.js (panel con las 20, 200
  pruebas) y test-compat.php (lado PHP por versión, 33 pruebas cada una).

= 4.3.1 =
* Arreglado: casi todos los contactos llegaban al primer número. Joinchat abre
  WhatsApp en el mismo clic, y el número del visitante se pedía al servidor al
  tocar el botón; en móvil entre el toque y el clic pasan ~100 ms y la
  respuesta tarda bastante más, así que se abría el número por defecto. Además
  el cupo se gastaba igual en otro agente, que nunca recibía ese contacto.
  Ahora, si al abrir WhatsApp el número aún no ha llegado, se pide en ese mismo
  clic (petición síncrona), sin que el navegador bloquee la ventana.
* Cada navegador envía un identificador y el servidor recuerda durante un día
  qué número le dio: la petición del toque y la del clic reciben el mismo
  número y solo se gasta un cupo.
* Arreglado: en las páginas donde Joinchat carga su versión "lite" (botones o
  enlaces de WhatsApp sin la burbuja flotante) el plugin no se cargaba y todo
  iba al primer número. Ahora se carga con las dos versiones, y si Joinchat se
  encola tarde se reintenta en el pie de página.
* A prueba de fallos: si el servidor no responde (bloqueo de admin-ajax,
  firewall, error 500, página en caché con una lista antigua...) el número se
  elige al azar de la lista en el navegador, nunca siempre el primero.
* Funciona aunque un plugin de optimización (WP Rocket, LiteSpeed, Autoptimize)
  cambie el orden de los scripts, y aunque otro script reemplace las funciones
  de Joinchat: como última red, el evento oficial "joinchat:open" corrige el
  enlace justo antes de abrir WhatsApp.
* admin-ajax se llama siempre en el mismo dominio que ve el visitante (www/sin
  www, http/https ya no lo bloquean) y la respuesta se entiende aunque otro
  plugin imprima avisos PHP delante.
* Un botón con su propio número ya no gasta cupo del reparto. El número por
  defecto escrito con otro formato (+57 300...) también se reparte.
* El servidor reconstruye una lista perdida a partir de los ajustes actuales, y
  una opción corrupta en la base de datos ya no provoca un error fatal en la
  página.
* Nuevo banco de pruebas de integración (test-integracion.js) que ejecuta el
  JS real de Joinchat 6.2.3 (lite y completo): 38 pruebas. PHP: 92 pruebas.

= 4.3.0 =
* Nueva página Ajustes > Permisos de Joinchat: el administrador elige qué roles
  (por ejemplo, Editor) pueden ver y cambiar los ajustes de Joinchat. Los
  administradores siempre tienen acceso. No se modifican los roles en la base
  de datos: al desactivar el plugin vuelve el comportamiento por defecto.

= 4.2.2 =
* Compatible con Joinchat 6.3.x. Esa versión trae intl-tel-input v29, que
  renombró la API que usa el panel: desaparecieron getCountryData(),
  utils.isPossibleNumber() y utils.numberFormat. El panel se quedaba sin datos
  de países, así que no salían las banderas ni el selector de país. Ahora se
  resuelve el nombre de cada función en tiempo de ejecución y funciona igual
  con la v25 (Joinchat 6.2.x) y con la v29 (Joinchat 6.3.x).
* Los nombres de los países salen ahora del propio navegador cuando Joinchat no
  los aporta, que es lo que ocurre en la v29.
* Verificado en producción sobre Joinchat 6.3.2: 60 teléfonos, todas las
  banderas dibujadas y todos los números formateados.
* 10 pruebas nuevas que emulan la API de la v29 sobre el motor real, incluida
  la comprobación de que el indicativo tampoco se duplica en esa versión.

= 4.2.1 =
* Arregladas las banderas, que no se veían. El CSS del plugin usaba la forma
  abreviada "background", que borra la imagen del sprite de banderas, y además
  forzaba un tamaño de 20x15 px cuando las celdas del sprite son de 16x12. Se
  pasa a "background-color" solo en el hueco vacío y se respeta el tamaño real.
* El plugin ya está en español. La traducción venía del addon original de 2019
  y no incluía ninguna de las cadenas nuevas, así que el panel salía en inglés.
  Añadidas y traducidas las 31 cadenas del plugin.
* La insignia "×N" de los números repetidos ahora explica lo que significa al
  pasar el ratón por encima: cuántos cupos se lleva ese número, sobre cuántos
  y qué porcentaje representa.
* Pruebas nuevas: 15 de traducciones (validan el archivo .mo con un lector
  independiente y comprueban que ninguna cadena del código se quede en inglés
  ni rompa los marcadores de formato) y 11 que impiden que el fallo del CSS de
  las banderas pueda volver.

= 4.2.0 =
* Panel de teléfonos rediseñado. Cada fila lleva ahora su banderita (deducida
  del indicativo que escribes), el número en formato legible al lado
  (+57 300 1234567), su posición, y un botón para quitarla.
* Selector de PAÍS POR DEFECTO. Escribes el número nacional (3001234567) y al
  salir del campo se le añade el indicativo solo (573001234567). Usa
  libphonenumber para distinguir un número nacional de uno ya completo, así que
  un número que ya tiene indicativo nunca se toca y el indicativo NUNCA se
  duplica: ante la duda, se deja lo que escribiste.
* Botón "Pegar lista": pega los 70 números de golpe, separados por saltos de
  línea, comas o punto y coma, con opción de reemplazar la lista actual.
* Resumen del reparto bajo la lista: cuántos cupos, cuántos números distintos y
  qué porcentaje se lleva el que más recibe. Los números repetidos se marcan
  con una insignia "×N".
* Enter añade una fila nueva en vez de guardar el formulario entero.
* El valor que se GUARDA no ha cambiado: sigue siendo un campo de texto normal
  con su "name" real y el número internacional en dígitos. Las banderitas, el
  formato y el selector de país son ayudas visuales; ninguna es dueña del valor,
  así que un fallo en cualquiera de ellas no puede borrar un teléfono.
* Detecta el addon original "Joinchat Random Phone" de Creame. Los dos guardan
  los teléfonos en el mismo sitio, así que no hay nada que migrar: basta con
  desactivar el viejo, y ahora sale un aviso con un botón para hacerlo.
* Los scripts pasan a registrarse como "random-phone-for-joinchat". Antes
  compartían nombre con los del addon original, así que con los dos activos
  WordPress cargaba solo uno de los dos archivos y el reparto podía dejar de
  funcionar sin dar ningún error.
* 84 pruebas automáticas nuevas del panel (64 de comportamiento y 20 de extremo
  a extremo sobre el HTML que genera el PHP real), pasadas sobre el archivo
  normal y el minificado.

= 4.1.0 =
* El cupo se consume por INTENCIÓN DE CONTACTO, no por visita. Antes, cada
  carga de página gastaba un número de la lista, aunque el visitante no
  pulsara nunca el botón (y aunque fuera un bot o un rastreador). Ahora el
  número se pide en la primera señal real de contacto: al apuntar/tocar el
  botón de WhatsApp, al abrir el chatbox, o al aparecer en pantalla un botón
  con QR insertado en el contenido.
* La petición se lanza ANTES de que el clic termine (pointerdown, touchstart,
  mouseover, evento joinchat:show), así que window.open sigue siendo síncrono
  dentro del clic y los bloqueadores de ventanas emergentes no intervienen.
* Los códigos QR se redibujan con el número asignado. Los bloques que tienen
  su propio número configurado no se tocan. Si algo falla, se conserva el QR
  ya dibujado: nunca queda un QR roto ni sin dibujar.
* El visitante que ya tenía número asignado (sticky) lo recupera del navegador
  al instante, sin pedir nada al servidor y sin gastar cupo.
* Sin cambios en el reparto: sigue siendo un shuffle-bag global en el servidor
  (ningún número se repite hasta agotar la lista completa) y la asignación por
  visitante sigue siendo permanente.
* Arreglado: un visitante que navegaba entre dos páginas con LISTAS DISTINTAS
  gastaba un cupo en cada salto y nunca quedaba fijado a un agente. Ahora se
  recuerda un agente por lista (hasta 10 listas por navegador). Los visitantes
  que ya tenían número asignado con 4.0.2 lo conservan al actualizar.
* Arreglado: un número escrito como "+0034600111222" conservaba los ceros
  ("0034600111222") porque al quitar el "+" los ceros dejaban de estar al
  principio. Ahora se limpian los símbolos primero y los ceros después.
* Arreglado: la lista de bolsas de reparto crecía sin límite en la base de
  datos al editar los teléfonos muchas veces (60 ediciones = 98 KB). Ahora se
  descartan las bolsas de listas que ya no existen, igual que las listas.
* Verificado con 132 pruebas automáticas: 74 del PHP (ejecutando la clase real
  sobre un WordPress simulado) y 58 del DOM con jsdom, estas últimas pasadas
  también sobre el archivo minificado. Cubren listas de 2, 3, 5, 70, 71, 100,
  150, 300 y 500 números; cupos repetidos con pesos; 14.000 contactos seguidos;
  bloqueo de base de datos caído y carreras entre visitantes; bolsa corrupta;
  firmas inválidas; móvil sin hover; Safari privado sin localStorage; servidor
  caído; clic instantáneo; y QR con número propio.

= 4.0.2 =
* Arreglado que al añadir un segundo teléfono se borraba el anterior. Los campos
  del panel ahora son inputs de texto normales con "name" real (se envían
  siempre), sin depender de intl-tel-input (cuya API cambia entre versiones de
  Joinchat). Se escribe el número internacional completo, ej. 34600111222.
* Verificado con pruebas automáticas de DOM (añadir/eliminar conserva valores).

= 4.0.1 =
* Arreglado el botón "+" para añadir teléfonos en el panel de administración con
  Joinchat 6.x: se corrige la dependencia del script (el handle admin pasó de
  'joinchat-admin' a 'joinchat') y se reescribe el JS para intl-tel-input v25
  (la antigua API 'intlTelInputGlobals' ya no existe). Los botones +/- ahora se
  enlazan siempre, aunque intl-tel-input no esté disponible.

= 4.0.0 =
* Reescritura para Joinchat 6.x (nuevo JavaScript: get_wa_link / open_whatsapp).
* Reparto GLOBAL y equitativo entre visitantes mediante shuffle-bag en servidor
  (compatible con caché de páginas gracias a un endpoint AJAX).
* Asignación STICKY por visitante: cada visitante siempre cae en el mismo agente.
* Auto-actualización mediante Plugin Update Checker v5 apuntando a GitHub
  (sustituye al antiguo actualizador Kernl).
* Se mantiene la interfaz de administración multi-teléfono con botón "+".
* Compatibilidad con el addon Agents conservada (shuffle-bag por navegador).
* La lista completa de teléfonos ya no se expone en el HTML de la página.

Basado en el addon original "Joinchat Random Phone" 3.5.2 de Creame (GPLv3).
